1

SEED — LLM merancang schema

LLM dipanggil sekali untuk domain baru. Menghasilkan schema JSON terstruktur (choice/score/noul). Tidak butuh training — instruksi runtime sudah cukup untuk Laya.

2

DEPLOY — Laya eksekusi runtime

Schema di-deploy ke Laya. Runtime berjalan tanpa LLM sama sekali. 7ms per keputusan, 395 q/s throughput, fully offline. Zero token cost.

3

MONITOR — Reflect Engine aktif

Sistem terus memantau output Laya. Jika output berulang, confidence drop, atau error rate naik — reflect event dipicu secara otomatis.

4

EVOLVE — LLM review + Compare Gate

LLM dipanggil untuk deliberate review. Menghasilkan schema kandidat baru. Kandidat masuk Compare Gate — hanya yang terbukti lebih baik (delta > 5%) yang dipromosikan.

5

LOCK — Permanent Core dikunci

Schema yang dipromosikan dikunci ke Permanent Core. Tidak bisa diubah sembarangan. Setiap perubahan harus melewati proses evolusi lengkap dari awal. Audit trail tersimpan.

🔒

Immutable Core

Pengetahuan yang sudah terbukti baik tidak boleh diubah sembarangan. Setiap schema yang dipromosikan mendapat version lock. Seperti Git commit — sejarah tidak bisa dihapus, hanya bisa ditambah.

⚖️

Comparison Gate

Kandidat pengetahuan baru harus mengalahkan yang lama secara terukur sebelum dipromosikan. Threshold 5% delta akurasi. Tidak ada update otomatis tanpa justifikasi data.

⚡

Reflect Event

Repetisi output = sinyal sistem stuck. LLM hanya dipanggil saat ada anomali — bukan setiap request. Ini yang membuat sistem efisien: 99% runtime tanpa LLM, 1% deliberate evolution.

Analogi
LLM = Insinyur senior yang merancang prosedur operasional
Laya = Operator yang menjalankan prosedur dengan tepat dan cepat
Permanent Core = SOP yang sudah divalidasi dan tidak bisa diubah tanpa approval
Compare Gate = Review board — prosedur baru harus terbukti lebih baik
Reflect Event = Alarm saat operator mulai berulang / hasil tidak sesuai ekspektasi
